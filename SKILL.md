# /transcribe — Расшифровка аудио и видео

Пайплайн: ffmpeg → Silero VAD → mlx-whisper (turbo) → диаризация senko → мемо.
Всё локально, без интернета и ключей. Скрипты делают механическую работу,
Claude — только имена спикеров и мемо. **Не переписывай транскрипт целиком
через себя** — это медленно и дорого; чистка уже сделана детерминированно.

Пути. `$SKILL` — папка этого скилла (где лежит SKILL.md). Python бери так:

```bash
PY="$SKILL/.venv/bin/python"
[ -x "$PY" ] || PY="$(dirname "$SKILL")/../../.venv/bin/python"
```

(venv живёт либо рядом со скиллом, либо в корне проекта при структуре
`<root>/.claude/skills/transcribe/`). Результаты запусков: `temp/transcribe/`
в корне проекта, если папка `temp/` существует, иначе
`~/Library/Caches/claude-transcribe/` — скрипт печатает точный путь.

---

## Шаг 0 — Проверка окружения (при первом запуске или после ошибок)

```bash
"$PY" "$SKILL/transcribe.py" --check
```

Если проверка падает или venv нет — запусти доктора, он идемпотентный и чинит
всё, что может, сам (venv, пакеты, ffmpeg через brew):

```bash
bash "$SKILL/setup.sh"
```

Единственное, что скрипт не может сделать сам, — установить Python 3.11
(нужен пароль администратора). В этом случае он скачает официальный
установщик python.org и откроет его; предупреди пользователя, что надо
кликнуть установку, дождись подтверждения и запусти `setup.sh` повторно —
он продолжит с этого места. До завершения установки текущее окружение
не трогается, транскрипция продолжает работать без диаризации.

## Шаг 1 — Входные данные

Единственное, что обязательно, — **путь к файлу**; обычно он уже есть в
сообщении пользователя, не переспрашивай. Аудио: mp3, wav, m4a, ogg, webm,
flac, aac, opus. Видео: mp4, mov, mkv, m4v, avi.

Больше ничего заранее не спрашивай: тип записи и число участников скилл
определяет сам по готовому транскрипту (транскрипция быстрая и идёт первой),
а имена спикеров уточняются после диаризации. Дефолты: модель turbo, язык
auto, VAD и чистка включены, мемо делается всегда.

Флаги на особые случаи: `--model large` (максимальное качество, медленнее),
`--language ru|en` (если автодетекция ошиблась), `--precise` (пословные
таймштампы, ~вдвое медленнее), `--no-vad`, `--no-cleanup`.

## Шаг 2 — Транскрипция

```bash
"$PY" "$SKILL/transcribe.py" "<путь_к_файлу>"
```

Для файлов длиннее ~20 минут запускай в фоне (`run_in_background`) и следи за
прогрессом — скрипт пишет в stderr статус по зонам. В stdout скрипт печатает
путь к папке запуска, в ней:

- `meta.json` — статистика: язык, длительность, скорость, выброшенные
  галлюцинации, число чисток;
- `segments.json` — сегменты с таймкодами;
- `transcript.txt` — сплошной текст;
- `transcript.md` — абзацы по паузам с таймкодами (диаризация потом
  перезапишет его репликами по спикерам).

Прочитай `meta.json` и сообщи пользователю краткую сводку (длительность, язык,
во сколько раз быстрее реального времени, сколько галлюцинаций выброшено).
Сырой транскрипт в чат не выводи.

Затем прочитай `transcript.md` и определи по содержанию тип записи:

- диалог (реплики, вопросы-ответы) → `созвон` или `интервью`;
- монолог с изложением темы → `лекция`;
- короткий монолог-надиктовка → `заметка`.

Тип не спрашивай — реши сам и назови решение пользователю одной строкой при
выдаче результата («сделал как конспект лекции — если нужно иначе, скажи»).
Спроси заранее только если сигналы реально противоречат друг другу.

Если в `meta.json` поле `dropped_hallucinations` подозрительно большое или
пользователь жалуется на дыры — запасной вариант `repair_segments.py`
(ретранскрипция проблемных зон с шумоподавлением), см. `--help` скрипта.

## Шаг 3 — Диаризация (если запись — диалог)

Запускай для созвонов и интервью; для монолога (лекция, заметка) пропусти —
senko лишь подтвердит одного спикера, а на длинной записи это минуты.
Сомневаешься, монолог ли это, — запусти: число спикеров надёжнее определит
диаризация, чем чтение транскрипта.

```bash
"$PY" "$SKILL/diarize.py" "<путь_к_файлу>" "<папка_запуска>"
```

Скрипт печатает в stderr сводку: сколько спикеров, время речи и первая реплика
каждого. Создаёт `transcript.md` с метками `SPEAKER_NN`.

Если senko не установлен (окружение ещё не пересобрано на 3.11) — скажи об
этом честно и предложи разметку вручную: пользователь называет первые слова
каждой смены спикера, ты расставляешь метки. Не выдумывай спикеров по
паттерну «вопрос-ответ» без подтверждения.

---

## Шаг 4 — Имена спикеров

Покажи пользователю первые реплики каждого спикера из сводки диаризации и
спроси, кто есть кто. Затем примени имена скриптом — не редактируй markdown
вручную:

```bash
"$PY" "$SKILL/diarize.py" --rename "SPEAKER_00=Антон,SPEAKER_01=Мария" "<папка_запуска>"
```

## Шаг 5 — Мемо

Прочитай **`references/memo-style.md` из папки скилла** — это обязательные
редакторские правила текста мемо (честность, инфостиль, анти-нейрослоп,
самопроверка). Затем по `transcript.md` (ты уже читал его на шаге 2; после
диаризации перечитай — там появились спикеры) напиши мемо по шаблону типа
записи, соблюдая эти правила. Мемо — это выжимка для дела, а не пересказ.

**Созвон:**

- Решения — что решили и почему.
- Действия — кто, что, к какому сроку (только то, что реально прозвучало).
- Открытые вопросы — что осталось без решения и кто должен решить.

**Интервью:**

- Ключевые инсайты.
- Боли и проблемы.
- Цитаты для отчёта (дословно, с таймкодом).

**Лекция:** тезисный конспект по логике изложения, новые термины с
определениями, прозвучавшие вопросы.

**Заметка:** суть в 2–3 предложениях, задачи/идеи списком.

После черновика мемо пройди раздел «Самопроверка перед выдачей» из
`references/memo-style.md` — и только потом собирай финальный документ.

## Шаг 6 — Финальный документ и сохранение

Собери документ:

```markdown
# [Название по сути записи]

**Дата записи:** [если известна, иначе дата файла]
**Тип:** [созвон/интервью/лекция/заметка]
**Участники:** [имена]
**Длительность:** [из meta.json]

## Мемо

[мемо по шаблону]

## Расшифровка

[содержимое transcript.md — реплики по спикерам]
```

Прогони готовый файл через встроенный типограф (копия скилла milchin живёт
в папке transcribe — отдельная установка не нужна):

```bash
"$PY" "$SKILL/milchin.py" --file "<путь>" --fix --in-place
```

Сохрани рядом с исходной записью как `<имя_файла>_transcript.md`; если
пользователь просил другое место — туда. Скажи, куда сохранил.

Если в окружении установлены полные редакторские скиллы (`chukovsky`,
`slopotron`) — можешь предложить дополнительный прогон мемо через них
(жанр: инфостиль), но скилл самодостаточен и без этого. Транскрипт через
редакторские скиллы не гонять — только мемо.

## Примечания

- API-режим (OpenAI Whisper) удалён сознательно: скилл полностью локальный,
  без ключей и токенов.
- Turbo — это large-v3 с урезанным декодером: в 3–5 раз быстрее, качество на
  русском почти неотличимо. Для трудных записей (шум, акценты) есть
  `--model large`.
- Live-режим (транскрипция параллельно с созвоном) — в бэклоге, v2.
